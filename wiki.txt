# CaptureZones Wiki

This wiki reflects the current `CaptureZones` behavior from source for version `1.1.4`.

## Quick Overview

CaptureZones adds capturable zones with per-zone rules, rewards, reinforcements, map markers, shops, statistics, KOTH mode, conquest mode, Discord alerts, and localization.

Core goals:
- Highly configurable global + per-zone behavior.
- Works with Towny or without Towny (standalone/scoreboard owner platforms).
- Supports both circle and cuboid zones.
- Supports Towny-wide money payouts, capturer-bound potion rewards, Dynmap, BlueMap, and Pl3xMap.
- Non-destructive schema repair for upgrades.

## Installation

1. Stop the server.
2. Place `capturezones.jar` in `plugins/`.
3. Start server once to generate data files.
4. Edit `plugins/CaptureZones/config.yml`.
5. Restart or run `/cap admin reload`.

Notes:
- Legacy folder migration is supported: `plugins/TownyCapture/` -> `plugins/CaptureZones/`.
- If your server already has existing config/data, use `/cap admin repair` after updating.

## Requirements

Required:
- Java 17+
- Paper/Spigot 1.21.x

Build target:
- The 1.1.4 jar is compiled against Spigot API `1.21.11-R0.1-SNAPSHOT`.
- `plugin.yml` declares Bukkit `api-version: 1.21`.

## File Layout And Generated Data

```text
plugins/CaptureZones/
  config.yml
  zone-template.yml
  capture_points.yml
  potion_rewards.yml
  statistics.json
  zones/
    <zone_id>_config.yml
  shops/
    <zone_id>_shop.yml
  lang/
    en.json
```

Meaning of each file:
- `config.yml`: global plugin settings.
- `zone-template.yml`: defaults for new zone config files.
- `zones/<id>_config.yml`: per-zone behavior overrides.
- `capture_points.yml`: runtime zone state, ownership, coordinates, cooldown state.
- `potion_rewards.yml`: tracks which capturer currently owns each plugin-managed potion reward.
- `shops/<id>_shop.yml`: per-zone shop data.
- `statistics.json`: tracked stats and records.
- `lang/*.json`: localizable text.

### Admin KOTH Commands

- `/cap admin koth status`
- `/cap admin koth start [zone_id ...]`
- `/cap admin koth stop [zone_id|all]`
- `/cap admin koth assign <zone_id>`
- `/cap admin koth unassign <zone_id>`
- `/cap admin koth zones`

KOTH start behavior:
- `/cap admin koth start` with no IDs starts only from assigned zone pool (`koth.activation.zones`).
- If IDs are passed, unassigned IDs are skipped.

### Admin Conquest Commands

Conquest is disabled by default. Enable `conquest.enabled: true` before using these commands.

- `/cap admin conquest start [profile]`
- `/cap admin conquest stop`
- `/cap admin conquest status`
- `/cap admin conquest assign [profile] <zone_id>`
- `/cap admin conquest unassign [profile] <zone_id>`
- `/cap admin conquest zones [profile]`

Conquest command behavior:
- `profile` defaults to `conquest.default-profile` when omitted.
- `assign` and `unassign` update `config.yml` directly and save it.
- Only zones that exist are used when a match starts.
- Active conquest-managed zones can only be captured by participating configured teams.
- Conquest v1 is intended for Towny owner gameplay. Use `capture-owners.platform: towny` or `auto` with Towny installed.

### `conquest`

Conquest is a ticket-based multi-zone match layer. It reuses normal capture mechanics, but an active conquest profile restricts managed zones to the configured participating owners.

Main settings:
- `conquest.enabled`
- `conquest.default-profile`
- `conquest.tick-interval-seconds`
- `conquest.profiles.<profile>.owner-type`
- `conquest.profiles.<profile>.starting-tickets`
- `conquest.profiles.<profile>.capture-ticket-gain`
- `conquest.profiles.<profile>.capture-ticket-loss`
- `conquest.profiles.<profile>.point-drain`
- `conquest.profiles.<profile>.min-teams`
- `conquest.profiles.<profile>.teams`
- `conquest.profiles.<profile>.zones`

Example:
```yaml
conquest:
  enabled: true
  default-profile: "default"
  tick-interval-seconds: 30
  profiles:
    default:
      owner-type: "town"
      starting-tickets: 500
      capture-ticket-gain: 0
      capture-ticket-loss: 25
      point-drain: 1
      min-teams: 2
      teams:
        - Northhold
        - Southport
      zones:
        - lumber_mill
        - river_crossing
        - iron_mine
```

Ticket rules:
- Every team starts with `starting-tickets`.
- On successful capture, the new owner gains `capture-ticket-gain` tickets if greater than zero.
- The previous owner loses `capture-ticket-loss` tickets when another team takes their point.
- Every conquest tick, a team loses `point-drain` tickets for each enemy-controlled conquest point.
- The match ends when one or zero teams have tickets remaining.

Safety limits:
- Minimum tick interval is 5 seconds.
- Starting tickets are clamped to a maximum of 100000.
- Per-event ticket gain/loss/drain values are clamped.

- `rewards.permission-rewards.*`
- `rewards.potion-effects.*`

Money payout modes:
- `OWNER_ACCOUNT`: default. Pays the controlling owner account, matching previous behavior.
- `SPLIT_ONLINE`: splits one configured reward across online eligible town/nation residents.
- `EACH_ONLINE`: pays each online eligible town/nation resident the full configured reward.
- `EACH_RESIDENT`: pays every resolved Towny resident account, including offline residents.

Example:
```yaml
rewards:
  base-reward: 1000.0
  money:
    payout-mode: "EACH_ONLINE"
    max-recipients: 100
    batch-size: 25
```

Town payout notes:
- Town-wide payout modes require Towny ownership and a working economy path.
- If Towny is not the active owner platform, payout falls back to owner-account behavior.
- `max-recipients: 0` means no recipient cap.
- Large resident payouts should use conservative `max-recipients` values.
- Reward statistics, broadcasts, and Discord reward messages use the actual paid total.

Capturer potion rewards:
```yaml
rewards:
  potion-effects:
    enabled: true
    duration-ticks: 260
    effects:
      - { type: "SPEED", amplifier: 0, particles: true, icon: true, ambient: true }
      - { type: "STRENGTH", amplifier: 0, duration-ticks: 260, particles: true, icon: true, ambient: true }
```

Potion notes:
- Effects go to the player who initiated the successful capture.
- Effects are tracked per zone in `potion_rewards.yml`.
- When another player captures the zone, the previous capturer stops receiving the effects.
- The plugin only removes matching short plugin-managed effects; it avoids wiping stronger or unrelated potion effects.

## Capture Mechanics

Normal capture lifecycle:
1. Preparation phase starts.
2. Capture phase starts.
3. Reinforcement waves spawn based on zone settings.
4. Contested and grace rules apply if enabled.
5. Capture completes or is cancelled.

Common cancellation reasons:
- mover too far from zone
- all participants disconnected
- grace timer expired
- session timeout

Additional enforcement:
- global min online players
- max concurrent captures
- per-zone cooldown and recapture locks
- schedule/weather restrictions
- KOTH-managed zones block normal `/cap capture`
- active conquest-managed zones block non-participant captures

## KOTH Mechanics

KOTH is optional and isolated from normal capture sessions.

Behavior:
- Scheduled or admin-started events activate selected zones.
- Players must hold the hill radius for `koth.gameplay.capture-seconds`.
- Hold radius uses square checks.
- Contested behavior supports `PAUSE` or `RESET`.
- Rewards can include money, items, permissions.
- Active KOTH info appears in map info windows.
- Optional KOTH hologram style can be enabled.
- Surface outline ring is applied during active KOTH and restored on stop/end.

## Conquest Mechanics

Conquest is optional and layered on top of normal capture zones.

Behavior:
- A profile defines teams, zones, owner type, starting tickets, and ticket drain.
- Starting a match cancels active captures in conquest-managed zones.
- Normal capture mechanics still decide who takes a point.
- Non-participant owners cannot capture conquest-managed zones while the match is active.
- Capturing a point can add tickets to the new owner and remove tickets from the previous owner.
- Ticket drain runs every `conquest.tick-interval-seconds`.
- Teams lose tickets based on enemy-controlled conquest points.
- The match ends when one team remains above zero tickets.

Visibility:
- Ticket status is broadcast after capture ticket changes.
- Ticket status is sent in actionbars during conquest ticks.
- Ticket status is included in Dynmap, BlueMap, and Pl3xMap info windows/popups where supported.

## Rewards System

Supports:
- economy rewards
- Towny-wide economy payout modes
- item rewards (legacy + modern list)
- permission-based reward modifiers
- permission grant rewards (temporary/permanent)
- capturer-bound potion effects

Distribution modes:
- one-time capture completion
- scheduled zone reward behavior (hourly/daily)

Economy payout mode reference:
- `OWNER_ACCOUNT`: pays the owner account only.
- `SPLIT_ONLINE`: splits the configured reward across online eligible owner members.
- `EACH_ONLINE`: pays the configured reward to every online eligible owner member.
- `EACH_RESIDENT`: pays the configured reward to every resolved Towny resident account.

Performance notes:
- Keep `rewards.money.max-recipients` realistic for large towns.
- Use conservative payout values with `EACH_ONLINE` and `EACH_RESIDENT` because total paid can exceed `base-reward`.
- Failed economy deposits are counted and logged without failing the whole reward cycle.
- Bukkit, Towny, and Vault calls stay on the server thread.

Potion reward notes:
- Potion rewards are refreshed periodically instead of being permanent.
- The effect owner is the initiating capturer, not every town member.
- On reload or player join, valid online capturers receive their active effects again.
- On disable, the plugin stops refreshing effects; short durations naturally expire.

## Troubleshooting

Capture does not start:
- Check `settings.min-online-players`.
- Check per-zone cooldown/time-window/weather rules.
- Check max active captures (`settings.capture-concurrency.*`).
- If zone is KOTH-managed, use KOTH flow instead.
- If conquest is active, confirm the capturing owner is listed in `conquest.profiles.<profile>.teams`.

Cannot create more zones:
- Check `settings.max-capture-points`.

`/cap tp` missing from help/tab-complete:
- Set `settings.capture-teleport-enabled: true`.

Repair command changed my data unexpectedly:
- Current repair is add-missing-only for valid values.
- If a value type is incompatible, schema normalization may correct it.

Shop command says disabled:
- Set `shops.enabled: true` and reload.

No economy payouts:
- Verify Vault + an economy provider plugin.
- For town-wide payout modes, verify Towny is installed and `capture-owners.platform` is `auto` or `towny`.
- Check `rewards.money.payout-mode`; `OWNER_ACCOUNT` does not pay individual residents.
- Check `rewards.money.max-recipients`; a low cap limits who gets paid.
- For `EACH_RESIDENT`, confirm resident accounts can be resolved by Towny/economy.

No map markers:
- Ensure Dynmap/BlueMap/Pl3xMap is installed and enabled in `config.yml`.
- For Pl3xMap, check both global `pl3xmap.enabled` and per-zone `pl3xmap.enabled`.

Conquest does not start:
- Set `conquest.enabled: true`.
- Ensure the profile has at least `min-teams` valid team names.
- Ensure the profile has valid existing zone IDs.
- Ensure Towny owner names match real towns/nations for the configured `owner-type`.
- Run `/cap admin conquest zones <profile>` and `/cap admin conquest status`.

Potion reward does not apply:
- Enable `rewards.potion-effects.enabled` in the zone config.
- Use current Bukkit potion effect names such as `SPEED`, `STRENGTH`, `RESISTANCE`, or `HASTE`.
- Make sure the capturer is online; offline players receive valid active effects again on join.
- Check `potion-rewards.refresh-interval-ticks` and `rewards.potion-effects.duration-ticks`.

Language not switching:
- Verify `settings.language` matches file name in `/lang`.
- Run `/cap admin reloadlang`.
